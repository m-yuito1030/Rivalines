# 複数のエージェント(人・AI)で同時に作業するときの決まり

同じリポジトリを何人(何体)かで同時に触る。衝突を減らし、起きたときに安全に直すための決まり。
基本の流れ(ブランチ → PR → CI → スカッシュマージ)は [WORKFLOW.md](WORKFLOW.md)。ここはその上乗せ。

## 1. 始める前に(必ず)
1. `git fetch --prune` で最新にする。
2. `gh pr list` と `git branch -r` で、**いま開いている PR・枝**を見る。自分がこれから触るファイルを、他の PR が触っていないか確かめる(`gh pr diff <番号> --name-only`)。
3. 同じ場所を触る PR があるときは、**先に出ている方を先にマージ**してもらい、自分はそのあとで始める。急ぐなら、先に作業の持ち主と相談する。
4. 取りかかったら、**早めに Draft の PR を出す**(「この作業はやっている」の印になる)。タイトルの頭に `[WIP]` を付ける。

## 2. 枝と PR
- **1 作業 = 1 枝 = 1 PR。** 短く(1〜2 日で取り込める大きさ)。大きいものは、動く単位に分けて順に出す。
- 枝の名前は `feature/` `fix/` `hotfix/` `docs/` `refactor/` `chore/` のあとに、内容が分かる短い名前。他の人の枝には、書き込まない・force push しない。
- 取り込んだ枝は、マージのときに消す。**PR を出さないまま 3 日以上たった枝**は、持ち主が消すか、PR にする。他の人は勝手に消さず、持ち主に聞く。
- PR を出す前に、最新の `main` に載せ替える(`git fetch && git rebase origin/main`)。衝突は、自分の PR 側で直す。
- マージは **Squash and merge** だけ。CI が緑になってから。後から出した PR は、先にマージされたものの上に載せ替えてから取り込む。

## 3. 衝突しやすい場所(触るときの約束)
同時に何人もが触りやすいファイル。次の約束を守る。

| 場所 | 約束 |
| --- | --- |
| `package.json` の `version`・`package-lock.json` の版 | **機能の PR では上げない。** 版を上げるのは、リリースの PR だけ([VERSIONING.md](VERSIONING.md)) |
| `CHANGELOG.md` | 機能・修正の PR は、先頭の `## [未リリース]` の欄に **1 行だけ**足す。版の見出し(`## [0.4.0]`)は、リリースの PR で作る |
| `src/shared/i18n/en/*.ts`(英訳) | 新しい英訳は、**ファイルの末尾に足さず**、関連するキーの近くに入れる(末尾への追記は、同時に足すと必ず衝突する) |
| `src/shared/protocol.ts` | 通信の形は、全員に影響する。変えるときは PR の説明に「通信を変えた」と書き、`version`(画面とサーバーの版の照合)も意識する |
| `src/client/main.ts`・`src/client/style.css` | 大きくなりやすい。新しい機能は、`src/client/app/` や `src/client/ui/` に別ファイルで作り、main には呼び出しの数行だけ足す |
| `docker-compose*.yml`・`deploy/`・`scripts/` | 公開の環境に直結する。変えるときは、PR の説明に「運用に影響する」と書く |
| `package-lock.json` | 衝突したら、手で直さず、`main` の版を取ってから `npm install` をやり直す |

## 4. 環境・共有物(取り合わない)
- **本稼働・VPS・自宅サーバーの再起動・再ビルドは、ユーザーの許可があるときだけ。** 他のエージェントが同じ環境を使っていないかも確かめる。
- 試験用のコンテナや一時ファイルには、**自分の作業が分かる名前**を付け、終わったら消す(例: `tmp-i18n-`)。他の人のコンテナは消さない。
- ポートを使うときは、使われていないか確かめる(`ss -tlnp`)。
- **git の worktree を使い、作業ごとに別のフォルダで作業する。** `git stash` は全員で共有されるので、使わない(一時的に置くなら WIP コミット)。
- タグと GitHub の Releases は、**リリースをする人が 1 人だけ**行う。同時に 2 人がリリースしない。

## 5. 引き継ぎ
- やりかけのものは、PR の説明か `docs/HANDOVER.md` に、「どこまでやったか・残り・注意点」を書く。会話の中だけに残さない。
- 見つけた不具合や、手を付けなかったことは、PR の説明に書く(消えないように)。
- テストが落ちる・不安定なときは、**テストを消さず・緩めず**、原因を調べて直すか、PR の説明に書く。

## 6. 衝突が起きたら
1. 慌てて force push しない。まず `git status` と `git log --oneline --graph -20` で状況を見る。
2. 自分の PR 側で、`git rebase origin/main` をして、衝突を 1 か所ずつ直す。両方の意図を残す。迷ったら、相手の PR にコメントして聞く。
3. `main` が壊れたら、直すより先に **`git revert`** で元に戻す(履歴は書き換えない)。
4. 解決できないときは、手を止めて、ユーザーに状況を伝える。
