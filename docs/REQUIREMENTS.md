# Rivalines 要件定義 (ドラフト v0.3)

ゲーム名: **Rivalines**(rival + lines。路線を引いて街を育て、ライバル会社と競う)

Webブラウザで動く交通・街づくりシミュレーション(サンドボックス)。

## 1. コンセプト
- 巨大マップ上で街が自然に成長し、プレイヤーが道路/鉄道/空路を敷いて輸送網を作る。
- **サンドボックス**: 資金・勝敗・時間制限なし(資金は無限/任意設定)。自由に建設・実験できる。
- バックエンド不要の静的Webアプリ。セーブはブラウザ内(IndexedDB) + ファイル書き出し。

## 2. 決定事項
| 項目 | 決定 |
|---|---|
| 描画 | アイソメトリック2D + WebGL |
| 技術 | TypeScript + Vite + PixiJS |
| マップ | 最大 **4096x4096**(選択式 256〜4096) |
| ゲームモード | サンドボックスのみ |
| MVP | 地形生成 + 街の成長 + 道路 & バス |
| 輸送対象 | **乗客のみ**(貨物・産業は対象外) |
| 時間 | **実時間30分 = ゲーム内1日**(x1速度時)。x2/x4で短縮 |
| 道路 | **一方通行を設定・変更可能** |
| ホスティング | ローカルUbuntuサーバで仮検証(静的配信) |

## 3. 機能要件
### 3.1 マップ/地形
- 乱数シード指定の手続き生成(ノイズ: 高度、海、山、川、森)。同シード=同マップ。
- 高低差タイル(傾斜)、海面、整地(上げ/下げ)。
- 生成は Web Worker + チャンク単位で進捗表示。
### 3.2 街の成長
- 街の自動発生(人口・名前)。人口に応じて建物が増え、道路網が拡張。
- 成長要因: 交通サービス(停留所の利用)、規模、周辺の地形。
- 人口・乗客発生・建物の見た目が段階的に変化。
- 時間: 1日=実30分(x1)。月・年はそこから算出(1ヶ月=30日で簡略)。ティック数/日は設計で決める(例: 1日=1800秒×固定ティック)。
### 3.3 輸送(フェーズ順)
1. **道路 + バス**(MVP): 道路敷設、バス停、路線(停留所リスト)、車両、時刻/運行、乗客輸送。
2. 鉄道: 線路、駅、信号(簡易)、列車。
   - **編成**: JR東日本の実在型式に準じた編成バリエーションを用意(例: 4/6/8/10/11/15両、付属編成との増結・分割、通勤/近郊/特急の車種区分)。
   - 編成は「車両の連結リスト」として定義(データ駆動 `data/trains/*.json`)。
   - **型式・名称・塗装はすべて架空**。実在の型式名(E233等)・路線名・会社名・ロゴ・塗装は使わない。編成の構成パターン(両数・増結・分割・車種区分)のみ参考にする。
3. 航空: 空港(サイズ別)、航空機、離着陸・スケジュール。
4. (後続候補) 船。※貨物・産業は対象外。
### 3.3b 運行スケジュール(時刻表・条件付きオーダーなど)
- 路線ごと/車両ごとに、次の2方式を**併用・切替可能**にする。
  - **間隔ベース**: 待ち時間、最大間隔、満載待ち(full load)等の積み込み条件。
  - **厳密な時刻表**: 各停車駅の到着/出発時刻を指定。1日=30分(実時間)に対応した時刻体系(日内時刻 + 周期)。
- 鉄道ダイヤの機能を段階的に取り込む: 時刻表の周期(循環)、車両への時刻表割当、遅延表示・自動補正(オートフィル)、条件付きオーダー、停車駅ごとの順序/スキップ、共有オーダー。
- 内部表現: オーダーリスト(行き先 + 条件 + 待ち/時刻)を共通データ構造にし、間隔/時刻表はその上の属性として実装。UIは後からでも拡張できる設計。
- 道路車両(バス)から実装し、鉄道・航空でも同じオーダー機構を共用する。

- パン/ズーム(最大〜全体俯瞰)、ミニマップ、建設ツールバー、路線/車両一覧、街情報パネル、速度(一時停止/x1/x2/x4)。
- 日本語UI(i18n構造は用意)。
- 道路ツール: 道路ごとに双方向/一方通行(向き反転)を切替。バス経路探索は方向を考慮。

## 4. 非機能要件(巨大マップの肝)
- 目標: デスクトップ Chrome/Firefox/Safari 最新、60fps描画。
- **データ指向**: タイルは TypedArray(SoA)。4096²=約1677万タイル → 1バイト/レイヤーで約16MB/層。層数と総メモリ予算を設計で管理(上限目標: 約200MB)。
- 描画はビューポート内のみ・チャンク(例 32x32)単位でバッチ/キャッシュ。ズームアウト時はLOD(簡略/ミニマップ化)。
- シミュレーションは固定ティック、**アクティブ領域/イベント駆動**で更新(全タイル走査しない)。経路探索は階層化/キャッシュ。
- 重い処理(生成・経路探索・成長)は Worker へ。
- セーブ: 差分/圧縮(巨大地形はシードから再生成 + 編集差分のみ保存)。
- モバイルは対象外(後で検討)。

## 5. アセット/ライセンス
- 画像は自作(プロシージャル/生成スクリプト)かCC0のみ。**他作品のグラフィック・音・テキストは使用しない**(特に OpenTTD などの素材はライセンスが異なるため使わない)。
- 出所不明の素材は `assets/` にコミットしない。ライセンス記録を `docs/ASSETS.md` に残す。

## 5b. ホスティング(ローカルUbuntu検証)
- ビルド成果物(`dist/`)を静的ファイルとして nginx 等で配信、または `vite preview --host`。
- バックエンドなし。同一LANからアクセスして検証。外部公開はしない(認証なし前提)。
- 将来クラウド公開する場合は別途検討。

## 6. リポジトリ運用
- `.gitignore` で秘密情報(.env/鍵)、node_modules、dist、セーブ/生成マップを除外済み。`.env.example` のみコミット。
- ブランチ運用・CIは後で決定(最小: lint + typecheck + test)。

## 7. 未決事項(次に詰める)
1. 車両台数の目標規模(数千〜?)と1日あたりのシミュレーションティック数。
2. 道路の交差点表現レベル(信号の有無など)。
3. 経路探索の方式(道路グラフ化 + A*/階層)。一方通行対応。
4. 4096で動かない環境のフォールバック方針。
5. 鉄道ダイヤのどの機能までをMVPに入れるか(MVPは間隔ベース + 基本時刻表を推奨)。
6. 画面・UIの優先順位とアセット(架空型式の見た目)方針。

## 8. ロードマップ案
- M0: 雛形(Vite+TS+Pixi)、アイソメ描画、カメラ、チャンク描画
- M1: 地形生成(Worker)、サイズ選択、ミニマップ
- M2: 道路敷設、街の発生と成長
- M3: バス停/路線/車両、乗客、成長連動
- M4: セーブ/ロード
- M5: 鉄道 → M6: 航空
