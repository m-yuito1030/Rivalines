# バージョン管理

## 番号
`0.メジャー.修正`。公開前のあいだは 0 から始める。

- 機能を足したら、真ん中を上げる(0.2.0 → 0.3.0)
- 不具合の修正(hotfix)は、最後を上げる(0.2.0 → 0.2.1)
- 正式リリースで `1.0.0`

番号は `package.json` の `version` が唯一の正解。画面の表示、サーバーとの版の照合、Git のタグは、すべてここから決まる。

## リリースの手順
1. 通常の変更は、これまで通り ブランチ → PR → CI → スカッシュマージ。**番号は上げない。** その代わり、`CHANGELOG.md` の先頭の `## [未リリース]` の欄に、変更を 1 行足す(複数のエージェントが同時に作業するときの衝突を減らすため。[MULTI_AGENT.md](MULTI_AGENT.md))。
2. リリースするときだけ、「版を上げる PR」を 1 つ出す。変えるのは次の 2 つ。
   - `package.json` の `version`
   - `CHANGELOG.md` の `## [未リリース]` を、`## [新しい版] - 日付` に書き換える(そのあとに、空の `## [未リリース]` を残す)
3. マージしたら、`main` に Git のタグ(`v0.3.0` のような名前)を付けて push し、GitHub の Releases に CHANGELOG の内容を貼る。
4. 本稼働・次期バージョンへの反映は、そのタグを使う(`scripts/release.sh` / `scripts/live-checkout.sh v0.3.0`)。

CI(テスト)が、次を確かめる。
- `package.json` の版が `数字.数字.数字` の形であること
- `CHANGELOG.md` に、その版の見出し(`## [0.2.0]`)があること

## 画面とサーバーの版の照合
接続したとき、サーバーが自分の版番号を画面に伝える。ブラウザに古い画面が残っていて、版が違うときは、画面の上に「新しい版が出ました。再読み込みしてください」と出る。
更新で通信の形が変わっても、古い画面のまま壊れた動きをしないようにするためのもの。

## データの形式の番号
ゲームの版番号とは別に、セーブデータの形式にも番号(`version`)がある。形式を変えるときは、古いデータを読める変換を足してから番号を上げる。
