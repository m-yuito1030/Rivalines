# マルチプレイ (simulator-multi)

個人用(ソロ)版は `../simulator-solo-v1.zip`(と `../simulator-handover` :8090)。こちらはサーバー権威型のマルチプレイ版。

## 構成
- **server/** (Node + tsx): 世界(65535²)を1つ進行。`src/shared` を共有。
  - `accounts.ts` 名前+パスワード(scrypt)、トークン、認証は同一IPから1分10回まで(`AUTH_RATE`)。最大100人。
  - `commands.ts` プレイヤーの操作を検証して実行(資金の支払い・所有者の確認)。道路/線路/整地/橋トンネル、停留所・駅・基地・経由点・信号・空港・施設、路線・オーダー、車両購入、融資・配当・買収、資金支援(送金)。
  - `replicate.ts` 視界内だけ配信: 新しく見えたチャンク(全タイル)、変更タイルの差分、視界内の車両(10Hz、経路は変更時のみ)、構造(停留所・路線・基地・信号)、街・施設、経営(1秒毎)。
  - 保存: `/data`(Docker ボリューム `multi-data`)に `accounts.json` と `world.sav`(5分毎+停止時)。環境変数 PORT / DATA_DIR / WORLD_SIZE / WORLD_SEED / MAX_USERS / SPEED / AUTH_RATE。
- **クライアント** (`src/client/main.ts` ほか): ブラウザは世界を進めず、サーバーから届いた内容を `GameMap`/`Simulation` のミラー(`src/client/connection/mirror.ts`)に反映して描画。操作は `src/client/connection/net.ts` でコマンドとして送る。地形は座標+シードで決まるので通信しない。
- 通信の型: `src/shared/protocol.ts`。

## ルール
- 会社 = アカウント。路線・停留所・基地・車両・敷設したタイル(`infraOwner`)・施設に持ち主がある。他社の物は操作・撤去できない(使うことはできる: 他社の駅を路線に入れる等)。
- **他社の線路・道路を走ると通行料**(鉄道 ¥300/タイル、道路 ¥80/タイル)を払い、敷設した会社が受け取る。
- **切断した会社はそのまま止まる**: 路線の車両は動かず、乗客も発生せず、日次・決算の処理も止まる。再ログインで再開。
- 競合AIは20社(価値が日々変動。買収すると傘下に入る。買収した会社の民間施設は買収者のもの)。
- 会社の評価(開発不可)はマルチでは使わない。ゲーム速度はサーバー固定。

## 街の段階
村(人口100〜)・街(1,000〜)・都市(10,000〜)・特大都市(100,000〜)・首都(300,000〜500,000)。生まれたときにその段階の最低人口まで育ち、**その段階の範囲内でだけ**成長する(村は1,000未満、街は10,000未満、都市は100,000未満、特大都市は300,000未満、首都は500,000まで)。
割合は `src/shared/world/town.ts` の `TIERS`(weight): 村60% / 街26.5% / 都市10% / 特大都市3% / 首都0.5%。大都市ほど建物あたりの人口(mul)と高層域・道路の上限が大きい。マップが狭いと上位の段階は出ない(`maxTierFor`)。平地が足りない場所では最低人口に届かないことがある。市役所は人口を育てる前に先に置く。

## ご当地の観光地
村・街・都市(特大都市・首都にはない)の各街に、1〜3か所(街の座標で決まる)が自動で生まれる公共施設(`sight`)。ユーザーは建てられず、買収・撤去もできない。日中(9〜17時)だけ周辺の駅・バス停の乗客需要を増やす(夜は2%)。大きさ S/M/L で需要 0.5/0.75/1.0 倍(基準1000人相当)。
見た目は180種(神社30・神殿/寺院20・タワー20・温泉20・アウトレット20・カジノ20・名所(噴水・銅像・灯籠など)50)。素材と生成スクリプトは `tools/sight-sprites/`、アトラスは `src/client/assets/sights.png` + `src/shared/data/sights.json`(`build_sights_atlas.py` で再生成)。配置は `placePublicFacilities`(街のにぎわいに合わせて少しずつ)。
観光地の見た目は街の規模に合わせて選ぶ(`src/shared/data/sightTiers.ts`): 村は祠・灯台・給水塔・足湯・名所など、街は電波塔・社殿群・アウトレットなど、都市はスカイツリー風・カジノ・スパリゾートなども。規模に合わない見た目のものは自動で付け替える。

## 街の見た目(段階別)
`TIERS` の `maxLevel` / `l1` / `l2` / `office`: 村=低層の住宅(S)だけ・オフィスなし / 街=中層(M)まで・オフィスは少し / 都市=高層(L)も出てオフィス街 / 特大都市・首都=高層が中心でオフィス街。中心ほど高く、外側ほど低い。予定地は同じ高さの平地が広がる場所だけを選ぶ(`roomFor`)。

## 巨大マップの地形(陸と川)
`src/shared/world/bigTerrain.ts`: 陸は約69%(`LAND_BIAS`、大きいほど海が減る)。川は座標だけで決まる(低周波ノイズの等値線がゆるやかに蛇行する水路。幅2〜6タイル、区間ごとに細く消える。段5より高い山には掘らない)。川の岸は段1に下げて橋を架けやすくしている。ミニマップ用の粗い参照(`heightPoint`)には川は含まない。地形を変えたので、既存のセーブとは地形が一致しない(ワールドを作り直す)。

## ダイヤ(運行図表) — メニュー ▸ 📈 ダイヤ
- スジ図(縦=駅、横=時刻)。自社の路線の編成を線で表示し、同じ駅を通る自社の他の路線は薄く重ねる。現在時刻の破線あり。
- 🚆 線をドラッグ → その編成の発車時刻のずれ(`vehOffset`)。🕒 ●をドラッグ → その駅の発車時刻(`orderSet`)。
- 待避の提案(`src/shared/sim/network/diagram.ts` の `suggestPassing`): 停車駅の少ない速い路線が、停車駅の多い遅い路線に駅間で追いつく箇所を検出し、番線が2以上の駅で待避させる遅らせ量を提案(適用=`orderShift`)。番線が足りないときは理由を出す。
- 一括設定(`routeBulk`): 間隔(分)から本数を決め、時刻表がなければ自動作成し、足りない車両を買い足して等間隔のずれにする。
- 複製(`routeClone`): 逆向きに複製(時刻表も組み直す)/ 指定の分だけずらして複製。車両は複製されない。
- 路線(Route)に配信用の `vs`(車両と offset)と `legs`(次駅までの走行時間)をサーバーが付けて送る。

## 種別と通過駅
- 路線の `rank`(0普通 1準急 2快速 3急行 4特急) と、オーダーの `pass`(通過)。通過の駅には停まらず、乗降・発車案内もなく、鉄道は駅のタイルを通り抜ける(`Transit.isWay`。経由点と同じ扱い)。
- 種別を選ぶと(`routeRank` / `Transit.applyRank`)通過駅を自動設定: 始発と最も遠い駅は必ず停車、途中駅は人口(集客圏+施設)と番線数の多い駅を優先して残し、残りを通過にする(残す割合 準急80%・快速60%・急行45%・特急30%)。時刻表があれば走行時間から組み直す。
- 路線パネル: 「種別」セレクトと、各駅の「通過」チェック。ダイヤ画面: 「🚄 種別の路線を作る」で元の路線は変えずに種別の路線を複製して作る(+5分)。
- 停車駅が2つ未満になる通過は拒否。待避の提案は、通過の駅を飛ばす速い路線と各駅停車の関係をそのまま扱う。

## 一覧(メニュー ▸ 📍 一覧)
街(段階ごと・人口順)と、機器・施設(駅・バス停・空港・経由点・車両基地・施設の種類別)をグループ別に並べ、項目をタップするとその場所へ移動する。名前で検索でき、機器は「自社のみ」で絞れる(`src/client/ui/listPanel.ts`)。
一覧の「🚆 車両」タブ: 自社の全車両(視界の外も含む)を路線ごとにグループ化し、タップで現在位置へ移動。サーバーが `misc` に `myVehicles`(id・路線・車種・位置・状態・積載%・両数)を1秒ごとに載せる。

## 車両を押すと経路を矢印で表示
地図で車両(電車・バス・飛行機)を押すと情報パネルが出て、進む経路が路線色の矢印つきの線で地図に重なる。今向かっている区間は太く、その先(最大3区間)はサーバーが計算した予定(`vehPlan` / `Transit.planAhead`)が細く出る。停車駅は白い丸。経由点・通過駅は順に通る経路になる。車両のいるタイルを優先して選ぶ(`src/client/ui/vehicleSelect.ts`)。

## 斜め線路の描画
斜めの腕を角の先まで少し長く描き(`DIAG_LEN`)、斜めだけのタイルは中心の四角を描かない。以前はタイルの角で先端が点でしか接せず、つなぎ目がネックレス状に途切れて見えた。

## 斜めの信号
信号は直線の線路(南北・東西に加え、斜めの 北東-南西 / 南東-北西)に置ける(`signalPair`)。向きは8方向のビットで、経路探索・閉塞の予約・描画とも斜めに対応。分岐点や駅・橋には置けない。

## 初回の設定駅に戻ったら経路を再計算
車両が路線の最初の停車駅から出発するたびに、その路線の経路を計算し直す(`route.replanAt`)。以前は一度計算した経路を、辺が通れる限り使い続けたため、あとから敷いた近道や信号の変更が反映されなかった。同じ路線の編成が続けて戻っても重ねて計算しないよう、間隔は `REPLAN_GAP`(100tick ≒ ゲーム内8分)に1回。経路キャッシュは計算時刻つきで、再計算より古いものは使わない。

## JGRPP風の電車まわり
- 🪄 自動敷設(`railauto`): 始点から終点へドラッグすると、既存の線路を安く・新設を高く・段差を割高にして、建物・交差・水・2段以上の段差を避けて最短でつなぐ(`autoRailPath`、最大60000ノード・距離600)。
- 🚦 信号を並べる(`signalLine`): 線路をドラッグすると、ドラッグの向きの一方向信号を指定の間隔(1〜20タイル)で置く。最大200か所/回。斜めも可。
- 🔁 全車両を置き換え(`routeReplace`): 路線の既定の車種に全車両を替える。差額を払い、旧車両は評価額の50%で下取り。鉄道は両数が変わる場合は対象外。
- 📍 追跡: 車両の情報パネルのボタン。カメラが車両を追いかける(カメラを手で動かす/パネルを閉じると解除)。
- 閉塞の可視化: 車両を選ぶと、予約済みの閉塞(他の編成が入れない範囲)が緑の帯で出る。信号が赤で待機中なら情報パネルに表示。
- 加減速(鉄道): 発車は低速(30%)から約25tickで加速し、停車駅の手前 `DECEL_TILES`(3タイル)から減速する(最低20%)。
- 未実装: 経路信号(PBS)・双方向信号などの信号の種類、基地へ行くオーダー、オーダーの一括編集、条件の拡張(遅延・混雑)、カーブでの減速。

## 修正: 経路キャッシュのキー衝突(巨大マップ)
経路キャッシュのキーを `from*2^24+to`(数値)にしていたため、巨大マップ(index が約 4×10^9)では積が 2^53 を超え、終点が1タイル違うだけの経路が取り違えられた(隣の番線のホームへ向かう経路が返るなど)。キーを `始点:終点` の文字列にして解消。実際の世界で、B駅→C駅が 94 タイルの大回りだったのが 35 タイルになった。
## 停車位置・折り返し
- 駅では編成の中央がホームの中央にくる位置に停まる(`docks(stop, 編成のタイル数)`。編成がホームより長ければ端まで)。
- 停車駅からの出発で、前進の経路が `REVERSE_MIN_TILES`(16)を超え、折り返した経路が 1/`REVERSE_RATIO`(1.6)以下なら、その場で折り返す。

## 経路選択のテスト(`src/shared/sim/network/routepaths.test.ts`)
経路探索(道路・鉄道・斜め・一方通行・信号)を乱数の網で基準実装(ダイクストラ)と最短コスト照合、経路キャッシュ(撤去後の探し直し・巨大マップ端のキー衝突)、駅の停車位置(ホーム長2〜14・両数1〜8・西/東から進入)、周回の停車順(ABCB・単線/複線・2編成・条件ジャンプ・通過駅)、経由点と待避線、ループ線+一方向信号、バスの環状一方通行、巨大マップ端(index>2^31)での一式。キー衝突のテストは、修正前のコードに戻すと失敗することを確認済み。

## 修正: 斜めの線路の撤去
撤去ツールは斜めにドラッグしても軸方向の直線しか対象にしておらず、斜めの線路を撤去できなかった。45度前後のドラッグは斜めの線に沿うようにした(線路ツールと同じ)。あわせて、斜めの線の終端タイルが自社のものとして登録されず、他社が撤去できてしまう不具合も直した。

## 経路キャッシュの設計(多数の路線向け)
- 基本: **線路・道路・信号・駅が少しでも変わったら、関係する経路は次に使うとき(次の出発)にすぐ探し直す**。撤去や時間経過に頼らない。
- しくみ: サーバーが建設・撤去・信号・駅の操作のあとに、変更した矩形を `Transit.touchNetwork(x0,y0,x1,y1)` で知らせる(世代 `netGen` と履歴 `netLog`)。経路キャッシュの各件は「始点・終点・経路の外接矩形(+余白 `PATH_MARGIN`=24)」を持ち、自分の世代以降の変更がその範囲にかかっていれば探し直し、かからなければ使い回す。到達できない結果(null)も同様(範囲は始点・終点の周囲60タイル+余白)。履歴が溢れた古い記録は念のため探し直す。
- 使うたびに各辺・信号の向きも検査する(撤去された線路を通る古い経路は使わない)。
- キャッシュは **LRU**(上限 `PATH_CACHE_MAX`=60000、超えたら古い1割だけ捨てる)。全消去しない。離れた場所の変更では探し直さないので、数百路線・多数のプレイヤーが建設を続けても、探索は「変更が関わった経路が次に使われたとき」にだけ起きる。
- (一時期の「初回の駅から出発するときだけ再計算」「世代が変わっても数十tick再利用」は、小さな変更が反映されず不適切だったため廃止。)

## 変更した線路の上の経路は、その場で変わる
- サーバーは建設・撤去・信号・駅の操作で**変更したタイル**を `Transit.touchNetworkTiles` で知らせる(`applyBuild` の `io.touched`)。
- そのタイルを今の経路に含む**走行中の編成・バス**には `replan` の印が付き、**次のタイルに入ったところで**いまの位置から目的地まで探し直す(`takeReplan`。壊れた線路で探し直す既存の処理と同じ経路)。関係のない車両の経路は触らない(全部を探し直さない)。
- 経路キャッシュも、変更したタイルが範囲にかかる件だけ次に使うとき探し直す。
- 目的地の手前に経由点がある区間は、経由点を保つため走行中は探し直さず、次の出発で反映する。飛行機は対象外。

## 車両の動きをなめらかに(クライアント補間)
サーバーは車両の状態を約10Hzで送るため、そのまま描くとカクつく。クライアントは車両ごとに直近2回のサーバー状態(経路上の進み pi+t、鉄道は編成の軌跡、飛行機は飛行距離)を持ち、描画のたびに `Transit.smoothMirror()` で**1区間(約100ms)遅らせて線形に補間**する。届くのが遅れたときは少しだけ先まで外挿してから止める。経路が変わったとき(新しい経路が届いたとき)は補間せず、そのまま出す。停車中は動かない。表示の遅れは約0.1秒。

## 撤去ツール(範囲・要素ごと)
- 撤去はドラッグで**矩形の範囲**を指定する(最大128×128タイル。以前は縦横の直線だけ)。オレンジの枠でプレビュー。クリックだけなら1タイル。
- 左のパネルで**撤去する要素**を選ぶ: 道路 / 線路 / 信号 / 駅・停留所 / 基地 / 経由点 / 橋・トンネル / 街の建物 / 空港。「交通すべて」「道路だけ」「線路だけ」「信号だけ」「解除」のボタンあり。初期は交通系すべて(建物・空港は外れている)。
- 他社の線路・道路・停留所・基地は撤去できない。駅は1タイルでも選べば駅全体(ホームの線路ごと)が消える。撤去したタイルを通る走行中の車両は、探し直される(経路は変更タイルに応じて更新)。
- 斜めの線路は、1段の高低差をまたいでは敷けない(直線のスロープだけ可)。テストで確認。

## 施設(ホテル・百貨店など)の売上
- 売上は「**その施設の集客圏にある停留所に、乗客が到着したとき**」だけ入る(来場1人あたり 売上 = 転換率 × 客単価。ホテル¥2,000、百貨店¥1,000)。停留所がない、または路線が走っていないと来場は0で、維持費(ホテル25,000/日・百貨店35,000/日)だけがかかる。黒字には1日にホテル約13人・百貨店約35人の来場が必要。
- 施設の情報パネルに、売上/日 − 維持費/日 = 損益、黒字に必要な来場数、集客圏に停留所がないときの警告を出す。
- 修正: サーバーで施設(ホテル・百貨店・公園・スタジアムなど)を建てようとすると、`facOcc` を定義前に使う初期化順の誤りで「サーバーエラー」になっていた(`execute` 内の const の位置)。建設と売上のテストを追加。

## 施設の来場者モデル(`src/shared/sim/facility/facilityVisitors.ts`)
対象: スタジアム・遊園地・モール・公園・百貨店・ホテル(公共施設は対象外)。1日の締めに、乗客の到着(停留所経由、従来どおり)とは別に「周辺から来る人」を加える。
- **基本**: 周辺の人口(60タイル以内の街。遠いほど薄める)の **2割(`WALKIN_FRACTION`)を上限に、0〜上限のランダムな人数**。施設ごとの1日の上限は `attract × 0.3`(`CAP_PER_ATTRACT`)。
- **駅・停留所**: 集客圏に停留所・駅があると **×1.8(`STATION_BOOST`)**。
- **競合**: 30タイル以内の施設(自社・他社どちらも)で分散: 同じ種類1つにつき `1/(1+0.6n)`、他の種類は1つにつき 0.1。
- **広告**(施設ごとに **14日に1度**): 新聞(建設費の2%・3日・自施設×1.3・近くの他の施設×0.9)/ SNS(5%・5日・×1.6・×0.85)/ テレビ(15%・3日・×2.2・×0.7)。他者の広告が効いている間は、近くの自分の施設は減る。費用は「広告費」(決算では維持費側)。
- 売上は自社の施設だけ(来場者×転換率×客単価)。他社・街の施設は来場者を数えるだけ。切断中の会社には入らない。施設の情報パネルから広告を打てる(`ad` コマンド)。
- 調整: `WALKIN_FRACTION` `CAP_PER_ATTRACT` `STATION_BOOST` `AD_TYPES` `AD_COOLDOWN_DAYS` を変えるだけ。

## 修正: 施設の重なり順
手続きで描く施設(スタジアム・遊園地・モール・公園・百貨店・ホテル)が、建てた順に描かれていたため、あとから建てた奥の施設の広場が、手前の施設の建物の上に重なって見えた。奥(前の角の x+y が小さい順)から描くようにした。

## 施設のデザイン・大きさの選択(ホテル・公園・百貨店・モール)

- 建てる前にデザインと大きさ(小/中/大)を選べる(`#facilityOpts`)。`place` コマンドの `fac: { design, size }` で送り、サーバーが範囲を検証する(指定なしは大・場所で決まるデザイン)。
- 敷地: ホテル・公園は S=1×1 / M=2×2 / L=3×3、百貨店・モールは S・M=1×1 / L=2×2。デザイン数はホテル30・公園20・百貨店20・モール20(`DESIGN_COUNT`)。
- 建設費・維持費・来場者の上限は大きさで変わる(`sizeMul`: ホテル/公園 0.4/0.7/1、百貨店/モール 0.5/0.75/1)。広告費・評価額も建設費に連動(`facilityBuildCost`)。
- スプライトは `tools/facility-sprites/`(`hotel.py` `park.py` と `build_facility_atlas.py`)で生成し、`src/client/assets/hotel.png` `park.png` と `src/shared/data/facilitySprites.json`(大きさごとのセル寸法・足元の中心)になる。`design` を持たない古いセーブの施設は従来の手続き描画。

## 会社名・プロフィール

- メニュー →「自社の会社名・プロフィール」で、会社名(20文字まで)・プロフィール(120文字まで)・会社の色を設定できる。WebSocket の `profile` メッセージで送り、サーバー(`Accounts.setProfile`)が検証して `accounts.json` に保存する(`<>` と制御文字は除去)。
- 会社名が未設定なら、これまでどおりアカウント名が会社名になる。`PlayerInfo` の `company` `bio` で全員に配られ、プレイヤー一覧・ランキングに会社名で表示される。ログイン名(アカウント名)は変わらない。

## セキュリティ・不正入力への対策(2026-11 点検)

- ログイン/登録の総当たり対策(1分10回)は、プロキシ(nginx)の `X-Real-IP` で接続元ごとに数える(以前はプロキシのIPで全員まとめて数えており、1人の連打で全員がログイン不能になった)。
- WebSocket の `profile` も操作回数の上限に含める(ディスクへの書き込みが連打できないように)。
- コマンドの検証: 路線作成は整数のIDだけ・異なる停留所2つ以上・1社1000本まで/オーダーの添え字は整数だけ/路線の周期は15分〜7日/発車時刻は1日の範囲内/名前は文字列だけ(制御文字は除く)/未知のコマンドは「不正な操作」。
- nginx に `X-Content-Type-Options` `X-Frame-Options` `Referrer-Policy` `Content-Security-Policy` を付与(`security-headers.conf`)。
- 一覧パネルの路線名など、表示前にエスケープしていなかった箇所を修正。

## 他社の停留所の使用許可

- 他社の停留所は、持ち主の許可がないと路線・オーダーに使えず、同じ場所への `ensureStop` もできない(共用=持ち主なしの停留所は誰でも使える)。
- 許可は2通り: 駅ごと(`stopAllow`。停留所の情報パネルの「🔑 他社の利用を許可」)と、会社単位(`companyAllow`。メニューのプレイヤー一覧の「全駅を許可」)。持ち主だけが出せて、いつでも取り消せる。判定は `Transit.mayUse`。
- 許可は `Stop.allow` と `Transit.grants` に持ち、セーブ・配信される。
- 許可を取り消しても、すでに作られた路線はそのまま走る(新しい路線・オーダーにだけ効く)。

## 接続が切れにくくするための仕組み

- ログインのトークンは署名つきで(`id.期限.署名`)、署名鍵は `/data/token.secret` に保存する。サーバーを再起動(再ビルド・クラッシュ)してもログインが切れない。期限は14日。
- クライアントは、回線切替・スマホのバックグラウンド・サーバーの再起動などで切れたら、「再接続しています…」を出して、サーバーが戻るまで待って自動で入り直す(別の場所でログインされたときだけ手動)。保存済みのログインは、サーバーが生きているのに拒否されたときだけ捨てる。
- サーバーは、進行ループ・保存・未処理の例外で落ちずに記録して続行する。30秒ごとに ping を送り、応答のない接続は切る。`stop_grace_period: 30s` で、終了の合図を受けたら世界を保存してから終わる。
- 再ビルド・再起動は、接続中の全員を一度切断する(自動で再接続する)。直近のオートセーブは5分おき、終了の合図のときは保存してから終わる。
